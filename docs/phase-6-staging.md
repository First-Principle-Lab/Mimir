# Phase 6 staging runbook

The local gate is reproducible with `bun install --frozen-lockfile`, Postgres/Redis from Docker Compose, `bun run migrate`, the repo checks and `scripts/eval/run.sh hardening "phase-6-hardening" --push`. It needs a real OPENROUTER_API_KEY. The suite refuses non-local database/Redis endpoints, owns Redis DB 9 exclusively, cleans its synthetic users and runs two API processes. Use HARDENING_SCALE=2 for twice the load. Run integration/eval suites sequentially: they share the local Postgres outbox.

## Hosted deployment

1. Set up the staging API, worker and static web services described in AGENTS.md, with automatic deploy off. Configure GitHub's staging Environment deploy hooks and HEALTHCHECK_URL. The repository currently has no configured GitHub environments; a deploy-skipped workflow does not satisfy this gate.
2. Use separate staging Postgres/Redis and synthetic staging accounts. Obtain the managed Redis persistence setting from Render and record AOF/disk/failover guarantees or the tier's limitation. Docker development now uses AOF/everysec with a persistent volume; that does not establish hosted persistence.
3. Apply migrations using the database owner, without DATABASE_RLS_ROLE. Run `bun scripts/rls-role.ts mimir_rls` with role-management privileges, then set DATABASE_RLS_ROLE=mimir_rls on API and worker. A dedicated non-superuser/NOBYPASSRLS application login can also work without SET ROLE. Production startup refuses roles that bypass RLS. Do not run migrations under the restricted role. If the managed owner cannot create/alter roles, provision the application role through the hosting administrator.
4. Configure at least two API replicas, a common JWT_SECRET/REDIS_URL/DATABASE_URL, credentialed frontend origins and the same VAPID identity. Every API replica must have a unique instance id; Render's instance id is the default. Verify authenticated socket delivery across replicas, disconnect/reconnect and persistence during rolling replacement. No load-balancer affinity is needed for websocket-only clients; polling transports require sticky sessions with socket.io's Redis adapter.
5. Set USER_DAILY_BUDGET_USD (default 5), USER_BUDGET_SOFT_RATIO (default 0.8), and any User.dailyBudgetUsd overrides through an administrative DB path. Check soft notices, hard 429, stop/rejection, delayed background jobs and next-window resumption. Budget reset is 00:00 UTC. Budgets do not reserve funds for already-running model calls.
6. Configure OTEL_EXPORTER_OTLP_ENDPOINT as a base URL and OTEL_EXPORTER_OTLP_HEADERS for API/worker. Configure the same repository secrets for evaluation workflows. Verify exported `mimir_http_request_duration_seconds`, `mimir_job_lag_seconds`, `mimir_health_ok`, queue/outbox/delivery gauges, failures and `mimir_eval_pass` in Prometheus. Histogram/counter suffixes in the shipped rules assume standard OTLP→Prometheus naming.
7. Provision alerts with GRAFANA_URL, GRAFANA_TOKEN, MIMIR_PROMETHEUS_UID and SLACK_WEBHOOK_URL through `bun run grafana-alerts --check`, then `bun run grafana-alerts --test-slack`. Keep secrets in the environment. Use a dedicated Grafana organization: the provisioning command replaces its notification-policy tree. Cloud deployments may need GRAFANA_NAMESPACE for the test-receiver API. Record a real Slack test and a controlled firing/resolved alert; local mock receipts are insufficient.
8. Promote through PRs in the normal direction after required CI. Repeat synthetic chat/tool/background/delivery load against hosted staging and record the tested commit, replica/worker counts, queue concurrency, p50/p95, error/duplicate counts, RLS checks, budget behavior and alert evidence. Keep the existing classifier-free harness scenario gate green. Do not promote to production or start Phase 7 while this gate is open.

## Operations

Production concurrency remains 20 conversation turns, 10 routines, 10 agents, 20 maintenance and 4 fact extractions per worker. The per-user agent cap is three running/five active; distributed database locking enforces it across workers. The local suite establishes whether those values hold on this host; tune only from hosted queue lag and latency measurements. A larger worker count can raise global API/model pressure without changing the per-user cap.

Investigate `failed-agent-jobs` before retrying. For started/interrupted write attempts verify the external outcome first; retrying an uncertain write is deliberately blocked. Outbox/inbox recovery and durable delivery handle dropped wakes/ACKs; metrics do not replace those journals. During a hard budget, an agent's queued row has resumeAt and its job is delayed. If Redis work is lost, review stale-agent outcomes and pending inbox/outbox records.

Delivery is at-least-once until the client acknowledges it; message ids let clients deduplicate after network loss. The fixed lease/retry-deadline race prevents duplicate concurrent drains, but a lost ACK can legitimately cause a later resend. Presence crash entries expire within 90 seconds; graceful shutdown removes them immediately. Monitor each hosted replica independently because Grafana NoData on the shared health query only detects loss of all reporting replicas.

## Gate record

Attach the hosted deployment URL privately where necessary, tested commit, passing immutable hardening/harness branches, required CI run, RLS-role verification, Redis durability result and controlled Slack firing/resolution evidence to the Phase 6 PR. Confirm each requirement in phase-6-review.md, resolve findings and rerun affected actual-inference evaluations before marking the phase complete.
