## Review findings and resolutions

1. Old prompt assembly placed volatile runtime data before recent history. Moved it to the final, nonpersistent tail and tested the order.
2. Provider token limits could conflict with `max_completion_tokens`. Preserve the actual provider field and send a single output limit.
3. Zero-usage legacy history and pi's physical provider registry could bypass a smaller deployment budget. Add pre-prompt projection checks and an explicit input-plus-output context window.
4. Summarizing with the shrunken model clone could produce one-token checkpoints. Use the original physical model and explicit summary output budget/auth/session routing.
5. Throwing from a pi compaction hook could fall back to a different summarizer. Explicitly cancel failed compaction and retain the original history.
6. Compaction model calls were absent from run cost accounting. Include usage, model logs and agent budget enforcement.
7. Old result clearing must survive restarts without damaging the audit journal. Use native append-only context edits; retain references/pairs and test hydration/idempotency.
8. Facts and relation expansion lacked explicit user/agent scope. Apply namespace filtering throughout, preserve rank order and revalidate faulty provider results at the gateway.
9. Memory-disabled workers could still access raw conversations. Remove both search tools and disallow raw transcript lookup from agent-local scope.
10. Explicit corrections/deletions needed provenance and policy enforcement. Add source checks, atomic scoped supersession, tombstones and journaled tools; live inference verifies the normal approval path.
11. Automatic background extraction bypassed replacement providers. Add the transcript ingestion contract and dispatch hook, with retry IDs, filtering, completion semantics and failure/watermark tests.
12. Full inference exposed response loss after compaction: an array index taken before compaction no longer identified new replies. Track current assistant replies from events and make the text helper null-safe. Regression verifies compaction, final delivery and durable journal.
13. Count-based evaluation judges returned impossible totals and malformed label lengths. Preserve failed runs; use a forced grading function with named per-record/per-annotation labels, validated evidence and code-calculated counts. Retain invalid submissions and allow only bounded validation repair; never retry valid scores to improve outcomes. Manual audit also found false stale labels for explicitly obsolete dates and annotations requiring evidence across several records; v5 supports multiple quotations and rejects contradictory wholly-supported/invented/stale labels. No fixture or provider behavior was tuned to these results.
14. Faulty provider mutation responses could expose records outside the caller namespace. Validate write results through the same ownership/scope/safety filter as reads; add a faulty-write-provider regression.
15. Full harness inference found an unrelated local email draft after GitHub rejected a reviewed action. The rejection was recorded correctly; the extra action made the gate fail. Terminal approval outcomes now close writes for that continuation, including internal drafts; reads remain available and fresh user input restores the normal gate. The runtime tail is built after decision execution so failed cards are not advertised as open. Regression tests cover the actual draft ToolSpec, zero extra action attempts, restored user writes and the refreshed tail.
16. The answer model could write memory before the extraction snapshot was graded. Freeze extraction before the held-out question and record interaction writes separately.
17. Published partial/dirty evaluation runs could misrepresent tested code. Require a clean tree including untracked files and disallow memory filters in the immutable runner.
18. The next full harness attempt failed the unattended-draft case after the model requested an observation outside its current inbox and then stopped. Ownership enforcement correctly rejected the read. A focused run passed before any behavior change, showing an intermittent model error; the original failure recorded only tool results, so its exact mistaken arguments are unavailable. Routine wakes now give the exact observation reference as JSON instead of prose, and a regression verifies round-trip keys containing punctuation/newlines and continued rejection of other keys. Eval evidence now records tool-call arguments and retains all step events on failure. The focused scenario passed after this change; the full rerun is recorded below. This improves reference clarity without weakening ownership or notification checks.
19. The fuller trace exposed stale open-card status within a single model turn: the tail callback refreshed time but captured approvals/agents before tools ran. The model repeatedly tried to withdraw an already canceled card because the final tail still advertised it as open. Tail construction now awaits fresh owner-scoped approval and agent queries on every model call. An integration regression checks the old card appears initially, disappears immediately after cancellation, and the new card appears after creation. The focused corrected-card scenario passed with actual inference.
20. That repeated-tool history also exposed a pre-prompt compaction failure on approval resume: pi had no eligible raw history under its retained-tail policy and threw `Nothing to compact (session too small)`. Read the pinned 1.6.0 preparation path; only that known refusal and `Already compacted` are treated as no-ops. Tests verify both preserve the journal and unexpected provider/summary failures still propagate. The full memory gate is repeated because this changes the compaction path.
21. The expanded agent suite found a background proposal request handled directly in chat: two email searches and a local draft, with no agent. External sending remained blocked, but the requested workflow was not followed. The prompt put the short/sequential-task default before the background requirement. Make the user's background workflow the first priority in both the system prompt and spawn tool description, including research and proposals for review. Strengthen the existing scenario to forbid email lookup/drafting/sending in its initial chat turn. The focused actual-inference scenario passed: delegation first, a worker proposal and no unapproved provider write. This is a model instruction, not a classifier or keyword router.

22. PR #10's [first required CI run](https://github.com/First-Principle-Lab/Mimir/actions/runs/45321246863/job/138200048195) passed lint/typechecking but failed the compaction-delivery regression with `No more faux responses queued`. The regression implicitly used the deployment model budget: the local override gave a whole-turn cut and one summary call, while the committed configuration split a turn and correctly required separate history/prefix summaries. Reproduced the failure locally with the committed model configuration. Pin a common test-provider window, cover both cut boundaries, queue their distinct summary calls, and assert the complete checkpoint plus delivered answer. Both cases pass under local and committed configurations; all 303 tests pass with CI's Bun 1.3.11 and committed configuration, with local environment overrides absent. Lint, typecheck and duplication verification pass. This changes regression tests only; all three published real-inference runs still test the unchanged application code. Required CI must rerun on the updated PR head before completion.

## Limits and remaining phase boundaries

- Long-history cases ingest the complete transcript incrementally, then ask a held-out question through the normal harness. First-use history imports the latest 50 messages, so distant details must come from durable retrieval. Noise replies are fixture text; the run does not infer an answer to every noise turn. The separate compaction/reload check exercises active-context retention.
- These are six synthetic reconstructions and single descriptive samples per history size, not a statistically powered benchmark. Token lengths are estimates. The long fixtures isolate distant-fact retention among repeated transient noise; they cannot establish quality on all natural histories.
- Answer checks use expected-detail strings and a manual read of the recorded replies; substring matching alone is insufficient for later provider qualification.
- Model-judged semantic scores require human auditing even with valid labels and grounded quotations. Deterministic expected-detail recall and final answers are recorded separately. Do not equate a correct recent-context answer with complete durable extraction.
- Chat cost includes interaction/compaction usage; legacy ingestion/embedding and judge billing are not available as a reliable total in this run and are explicitly marked unavailable. No provider cost ranking follows from these figures.
- Automatic extraction stays conversation-scoped. Explicit user-scope facts are shared across conversations; owner-scoped raw conversation search can find another chat. The separate-session live check verifies that fallback, not automatic sharing of every extracted preference.
- Original messages remain after forgetting a durable fact. `conversation_search` is a bounded exact-word fallback. Legacy source attribution can point to the first message of an extraction batch rather than the exact fact-bearing message; migration preserves that limitation.
- Credential filtering recognizes common token/key/password patterns and is not exhaustive sensitive-data classification. Providers must honor abort; a timeout can leave mutation outcome uncertain, so tool actions are not replayed automatically.
- The recorded interaction model is a mutable model alias, not an immutable provider revision. Exact client/model configuration is included with each run.
- Cache counters are provider observations; stable prefixes/session IDs cannot guarantee hits. Hosted inference latency and cache behavior vary.
- Mem0, Letta, Cognee, Supermemory and Graphiti have not been benchmarked or selected. Their versions, deployment modes, repeated measurements, ingestion/indexing behavior, full migration/import and qualification belong to Phase 7 after Phase 6 staging readiness. The current legacy baseline is not a sixth candidate.
- The CI-equivalent web build passed. Full native build produced the executable/deb/rpm but AppImage packaging failed in this machine's linuxdeploy step, the same environment limitation documented in earlier phases; CI excludes desktop.
