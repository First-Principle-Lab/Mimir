## Resolved review findings

1. A stale delivery selection could reclaim an already-sent row after its lease was released, duplicating a cross-instance reply. The atomic claim now also checks `availableAt`; concurrent delivery tests and the load gate cover it.
2. Prisma batches unique lookups across concurrent scopes. Unique reads outside transactions use unbatched `findFirst` equivalents; reads inside interactive/batch transactions retain their original connection. Cross-user concurrent reads and transaction visibility are tested.
3. Superuser development connections silently bypass RLS. Role setup creates/refreshes a restricted role; connection initialization awaits SET ROLE, verifies privileges and fails closed in production when RLS would be bypassed.
4. Checking userId alone allowed a tenant to attach a new row to a foreign conversation. Restrictive conversation-owner policies and target-fact policies close those references.
5. Per-call rounded cents lost inexpensive calls. Daily and per-call USD values retain sub-cent costs, with atomic log/rollup transactions and a concurrent increment test.
6. An interaction could keep calling tools/models after spend crossed the daily limit. Serialized accounting now precedes tool/provider continuation guards, including compaction. A regression proves that the next tool/provider response is never executed.
7. Budget-paused background jobs could be marked stale before their resume time. Persisted `resumeAt` anchors stale recovery; jobs move to delayed rather than finalizing a failed result.
8. Ambient inputs could produce repeated immediate budget wakes. Wakes reuse a per-conversation/window job id and carry an explicit deadline; recovery excludes exhausted background work before its LIMIT so it cannot fill another user's recovery batch.
9. Rejecting an approval was incorrectly disabled at the hard limit. Rejection remains available; its model follow-up waits until reset. Approval remains blocked until budget is available.
10. A soft warning appeared only on a later send. Thread refreshes now fetch usage, including on reconnect and turn settlement.
11. Routine/extraction jobs carry resource ids rather than userId. The job wrapper resolves resource ownership before entering the processor's RLS scope. System sweeps remain explicitly global.
12. BullMQ transport errors/stalled jobs and some handled failures had no alertable metric. Added log/metric paths and persistent DLQ gauge alerting; terminal jobs remain available for inspection.
13. Bun 1.3.11 can leave socket.io's HTTP close callback pending after transports close. Socket shutdown has a bounded grace period and closes remaining HTTP connections; tests use a short explicit grace period. Both API processes release their presence on graceful shutdown; crash expiry is independently tested.
14. The unfinished load fixture inspected the runtime tail as the user's request and assumed the faux provider reports model costs. It now separates the tail and prompt, injects an explicitly synthetic accounting charge for the faux budget check, and verifies actual provider spend in the live section. Source findings must contain the launch date and budget after the initial acknowledgement.
15. A test closed shared queue objects before later tests used them; new tooling also lacked declared root SDK imports and Turbo environment inputs. Queue lifetime, pinned eval dependencies, focused script typechecking and lint inputs are corrected.

## Remaining external gate and operational limits

Follow [the staging runbook](phase-6-staging.md). Configure staging services and GitHub Environment deploy hooks, verify two API replicas under the hosted balancer, apply the migration with the owner role and verify the application's restricted role, establish Redis persistence guarantees, configure OTLP/Grafana and send a controlled alert to the actual Slack destination. Record hosted load, fallback/reconnect, budgets, metrics and required CI evidence in the PR before closing the phase gate.

RLS is a backstop to ownership filters, not a defense against arbitrary SQL executed as the application: trusted system operations intentionally use an empty user scope. Transaction scopes must not switch tenant mid-transaction. Session settings require session-based pg pooling; transaction-mode external poolers need a different transaction-local integration. The old plan's proposed blanket Prisma filter injection and advisory lock on every write are superseded by scoped RLS connections, the harness's distributed conversation lock, ordered durable inbox and action journal; no classifier or semantic classification cache was reintroduced.

Budget costs are the runtime/provider's reported costs, not an independent invoice reconciliation; an in-flight batch can overshoot. Existing pre-rollout rounded logs cannot reconstruct lost sub-cent spend. Already-running ingestion is bounded by its existing batch; entry checks stop later batches. Local AOF/everysec configuration is added for Docker development; hosted Redis settings are unverified, and any managed tier limitation must be recorded explicitly. Postgres outbox/inbox journals remain the durable source of work, with recovery sweeps.

Health alert NoData detects loss of all API series. It cannot reliably detect a single vanished instance while peers export; hosted per-instance health checks are required. The ambient latency alert starts at inbox intake, not webhook arrival. Global no-data rules need an initial metric/eval sample and the CI OTLP secrets; skipped workflow jobs are not a passing inference gate. Load results are synthetic-account capacity evidence for this machine, not a hosted capacity or five-provider memory qualification claim.
